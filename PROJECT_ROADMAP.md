# Mini CRM — план улучшений перед публикацией

Проект уже является рабочим MVP: реализованы авторизация, CRUD контактов,
привязка данных к пользователю, загрузка аватара и адаптивный интерфейс.

## P0 — исправить в первую очередь

### Обработка ошибок CRUD

- [ ] Перестать поглощать ошибки в `stores/contactsStore.ts`.
- [ ] Пробрасывать ошибки `createContact`, `updateContact` и `deleteContact`
      вызывающему компоненту.
- [ ] Закрывать модальное окно и сбрасывать форму только после успешного ответа.
- [ ] Показывать понятное сообщение при ошибке сохранения.

### Серверная валидация контактов

- [ ] Добавить общую схему валидации через Zod или Valibot.
- [ ] Проверять обязательные имя и email.
- [ ] Проверять формат и длину email.
- [ ] Ограничить длину имени, телефона и остальных строк.
- [ ] Разрешать только известные `role` и `department`.
- [ ] Строго проверять тип `active`.
- [ ] Отбрасывать неизвестные поля запроса.
- [ ] Использовать одну схему в POST и PUT endpoints.

### Безопасная загрузка файлов

- [ ] Ограничить максимальный размер изображения.
- [ ] Проверять MIME-тип и допустимое расширение на сервере.
- [ ] Возвращать корректные HTTP-ошибки, включая `413 Payload Too Large`.
- [ ] Удалять старый аватар после успешной замены.
- [ ] Удалять загруженный файл, если сохранение контакта завершилось ошибкой.
- [ ] Не считать клиентский `accept="image/*"` проверкой безопасности.

### Модель данных

- [ ] Сделать email контакта уникальным в пределах владельца, а не всей БД:

```prisma
email String

@@unique([ownerId, email])
```

- [ ] Создать и проверить миграцию Prisma.
- [ ] Корректно обрабатывать конфликт уникальности на сервере.

### Модальное окно

- [ ] Не закрывать модальное окно по Enter.
- [ ] Оставить закрытие по Escape.
- [ ] Запретить закрытие во время сохранения либо запрашивать подтверждение.
